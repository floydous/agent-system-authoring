# Debunked Prompting & Tool Schema Folklore

Quick audit checklist of common myths to remove when refactoring prompts and tool schemas. Full experimental data, tested models, and citations live in [evidence/empirical_results.md](https://github.com/floydous/agent-system-authoring/blob/main/evidence/empirical_results.md) and [evidence/evidence_ledger.md](https://github.com/floydous/agent-system-authoring/blob/main/evidence/evidence_ledger.md).

| Common Myth | Reality | What To Do Instead |
| :--- | :--- | :--- |
| **"Add an expert persona (`Fields Medalist...`) to boost accuracy"** | Adds zero factual, math, or coding accuracy lift (`T5`). | State concrete objectives, invariants, and acceptance criteria; use personas only for tone/style. |
| **"Always write `Think step by step` on reasoning models"** | Native reasoning models already deliberate internally; CoT directives add no lift and can hurt strict format compliance (`T3`). | Omit CoT phrases on native reasoning models; specify clear goals and output formats directly. |
| **"Never use negative bans—use affirmative-only suggestions instead"** | Affirmative-only suggestions fail frequently when banned terms are unnamed; explicit `Do NOT` bans succeed reliably (`T2`). | Name forbidden words explicitly (`Do NOT use ...`) and state whether plurals and hyphenated compounds count. |
| **"Promotional tool descriptions (`BEST`, `ALWAYS USE`) don't skew routing"** | Promotional superlatives reliably hijack tool selection across architectures (`T2`). | Keep tool descriptions strictly factual and neutral; add explicit negative boundaries referencing sister tools. |
| **"Typed JSON Schema properties make parameter descriptions unnecessary"** | Omitting descriptions collapses format/unit validity and increases reasoning tokens (`T2`). | Put concise (`~15–50` tok) syntax examples, separators, units, and bounds in every parameter `description`. |
| **"Parameter order doesn't matter in constrained JSON schemas"** | When pre-output thinking is off (`reasoning_effort="none"`), putting computed outputs before a `rationale` field collapses math accuracy (`T2` + `T4`). | Put `"rationale"` first *only* when pre-output thinking is off; omit it on standard reasoning-model tools. |
| **"One huge 50-rule system prompt works as well as phased prompts"** | High concurrent rule counts degrade strict compliance and multiply thinking tokens (`T2` + `T5`). | Split multi-stage workflows into compact phase prompts or on-demand skills. |
| **"Big context windows eliminate tool-catalog pruning"** | Unpruned catalogs multiply prompt tokens every turn (`T4`) and hurt routing on weaker models (`T5`). | Prune catalogs via dynamic retrieval or consolidated multi-action tools; replace giant enums with `string` + lookup tool. |
| **"More few-shot examples always help"** | Superfluous shots waste tokens on reasoning models; rule-conflicting examples hijack weaker models or inflate thinking (`T5`). | Start zero-shot; add minimal examples only when needed and audit every example against written rules. |
| **"Arabic digits (`5`) beat spelled numbers (`five`) for exact counts"** | Refuted across tested architectures (`T2` null / no digit advantage). | Enforce exact counts with structured delimiters or deterministic post-validation, not numeral spelling tricks. |
| **"`###` Markdown headers inside tool descriptions improve routing"** | Adds prompt tokens and latency with no routing lift over plain prose. | Write clear `3–4+` sentence plain-prose tool descriptions. |
| **"JSON Schema is always better than TypeScript inside prose prompts"** | Outside native tool APIs (`T1`), TypeScript interfaces match JSON Schema extraction accuracy at roughly half the prompt tokens. | Use TypeScript interfaces inside prose prompts; keep JSON Schema for provider tool APIs. |
| **"XML tags inherently break OpenAI-lineage reasoning models"** | Artifact of literal `[P0\|P1\|P2\|P3]` bracket wording, not XML itself. | Use flat Markdown `###` headers or clean XML tags, and avoid literal pipe-bracket placeholders. |
| **"`temperature=0` makes single-run prompt evals deterministic"** | GPU FP non-associativity and batching cause run-to-run variance (`Methodology` / `T4`). | Run `N >= 5` repeats, aggregate per prompt before paired tests, and report `TARa@N`. |
| **"`additionalProperties: false` + all-keys `required` works identically on every provider"** | OpenAI-specific; Anthropic strict allows optional keys outside `required` and rejects `minimum`/`maximum`/`minLength`/`maxLength` with HTTP `400`; Gemini has no `strict: true` (`T1`). | Match each provider's exact wire shape and supported keyword subset (`references/tool_schema_guide.md`). |
